# 原型页面级隔离规范

## 1. 目的

确保单个模块原型的页面、样式、交互和 Mock 数据修改只作用于该模块，不影响顶部、左侧导航、应用壳层或其他课程页面。

本规范当前优先用于“备课工作台”，后续模块按同样方式扩展。

## 2. 页面边界

- 备课页面唯一业务入口：`#course/preparation`。
- 页面必须拥有唯一根节点：`data-page="preparation"`，推荐类名为 `.preparation-page`。
- 所有备课页面 DOM 必须挂在该根节点下；不得向 `body`、`.layout`、`.side`、`.main` 或顶部公共节点追加业务内容。
- 顶部课程上下文、左侧导航和全局弹窗属于应用壳层，不由备课模块修改。

## 3. CSS 规则

- 备课样式必须使用 `.preparation-page` 或 `.prep-` 前缀。
- 禁止在备课模块中直接修改 `body`、`html`、`.layout`、`.side`、`.main`、`.btn`、`.panel`、`.tag` 等公共选择器。
- 禁止重定义公共 CSS 变量；如需局部视觉值，使用 `.preparation-page` 下的局部变量。
- 响应式规则必须以 `.preparation-page` 内部组件为作用域，不改变全局断点行为。
- 备课样式不得覆盖应用壳层的 `position`、`z-index`、宽度、滚动和导航状态。

## 4. JavaScript 规则

- 备课渲染入口统一为 `preparation()`，不得修改其他模块的渲染函数。
- 备课交互函数统一使用 `prep*` 前缀，例如 `prepScroll`、`prepAction`、`sendPrepPrompt`。
- DOM 查询优先从 `.preparation-page` 根节点开始，禁止通过通用 ID 或全局选择器操作其他页面节点。
- 备课状态使用独立命名空间，例如 `ai-jiaowu-preparation-*`，不得复用大纲、日历或课件的 localStorage key。
- 备课事件监听必须在页面存在时绑定，并在页面离开时不对其他节点产生副作用。
- 不得覆盖 `window.render`、`window.coursePage`、`window.shell`、`window.openAI` 等公共入口；如确需扩展，必须通过已有接口调用。

## 5. 组件与数据规则

- 备课内容块、教材上下文、审核检查和 AI 对话均属于备课页面内部组件。
- 来源、章节、课程版本和备课状态只能从当前课程上下文读取，不得修改大纲、教学日历或课件数据。
- “转为课件”“转为作业”在原型中只能模拟创建目标模块副本，不直接改写目标模块页面状态。
- Mock 操作只能更新备课页面内的提示、状态或局部内容。

## 6. 修改前检查

每次修改备课页面前必须确认：

1. 修改文件和代码区段只属于备课模块。
2. 新增 CSS 选择器带有 `.preparation-page` 或 `.prep-` 范围。
3. 新增 JS 函数带有 `prep` 前缀，且没有覆盖公共函数。
4. 没有修改顶部、左侧导航和其他模块的 HTML、CSS 或状态。
5. `node tools/dev-check.mjs` 通过。
6. 至少检查一次 `#course/preparation` 与相邻模块页面，确认无样式和交互回归。

## 7. 修改后验收

- 进入备课页面：自动生成草稿、内容审核、教材上下文和 AI 对话可用。
- 离开备课页面进入大纲、日历、课件页面：页面结构、样式、导航状态和交互不变。
- 顶部课程切换和左侧导航可正常使用。
- 备课页面刷新后不污染其他页面的 localStorage 和全局状态。
- 课程归档等只读状态不改变其他模块的权限表现。
