# 公共 AI 规则

## 介入边界

传统解析优先用于格式、文本、目录、页码、OCR、切分、校验、权限和状态；大模型用于语义结构识别、知识点提取、摘要、问答、建议和教学内容生成。

## 性能目标

- 在线问答首 Token P95 ≤ 3 秒。
- 简单问答端到端 P95 ≤ 10 秒。
- 带知识库检索问答端到端 P95 ≤ 15 秒。
- 复杂教学内容生成端到端 P95 ≤ 30 秒。
- 异步解析按阶段返回进度，不承诺固定秒数。

初始工程目标：100 个同时在线用户、500 个同时打开页面、1000 个异步任务排队、10 个并行 LLM 请求；单用户最多同时运行 5 个 AI 任务，超出后排队。

## 输出规则

- AI 输出必须标记来源文件、章节、页码、模型结果状态和人工确认状态。
- 无证据时必须明确说明资料不足。
- 结构化任务只允许输出约定 JSON。
- 任何正式教学内容都必须经过人工确认或审核。
- 教师点击业务模块“保存”即视为对当前 AI 内容完成确认，不再单独设置“确认 AI 内容”按钮；保存后若再次编辑，结果状态自动标记为 `edited`。
- 不把整本原始 PDF 重复发送到每次对话上下文，只检索相关片段。
- 模型由系统设置中的“用途默认模型→同用途备用模型”路由；业务模块不得写死供应商密钥或模型地址。
- 结构化 JSON 经 Schema 校验；非法 JSON 自动重试最多 2 次，仍失败时展示已生成的部分文本并标记“生成不完整”，允许切换备用模型后重试。
- 单次输入和输出 Token 不设置产品侧固定上限，按所选模型能力和供应商限制执行；超出模型能力时提示切换模型或拆分任务。
- LLM 请求必须设置超时和并发上限；超出并发进入异步队列，不阻塞普通页面。

## Prompt 放置规则

Prompt 直接写在所属模块 PRD 的“AI 与 Prompt”章节中；只有被多个模块复用的 System Prompt 规则才放在本公共文档。
