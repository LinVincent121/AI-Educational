# 公共权限、状态与审核规则

## 角色

`owner` 负责课程初始化和成员管理；`teacher` 创建和编辑教学内容；`secretary` 查看课程并执行审核；`viewer` 只读；`admin` 全局管理。

## 已确认业务决策

- 一门课程只能有一份主教材。
- 课程负责人可以转移，转移不删除历史操作记录。
- 教学秘书可以查看和审核，但不能修改教师资料。
- 课程资料不允许跨课程引用。
- 共享资料由创建人管理，共享成员只能查看和引用，不能编辑、删除或再次授权。
- 课件和作业不要求教学秘书审核；教学日历必须提交教学秘书审核。
- 课程归档后允许查看成绩和历史资料，但禁止新增和修改。
- `viewer` 在被授权课程内拥有完整只读查看权限（包括成绩、学情、版本和审核记录），但不能导入、编辑、审核、计算或导出。
- 课程负责人可以转移；转移不改变历史版本、审核记录和操作日志。
- 课程版本创建时复制大纲、日历、章节映射和成绩权重配置的快照；历史版本只读，成绩只允许写入当前教学版本。
- 创建新课程版本时复制当前版本的大纲、教学日历、章节/知识点/能力指标映射、备课、课件、作业、题库/试卷模板和成绩权重配置；不复制学生名单、成绩记录、审核任务和分析快照。

## 权限判断

所有服务端操作都按以下顺序判断：

```text
用户身份 → 角色 → 课程成员关系 → 资源归属 → 当前状态 → 操作权限
```

前端隐藏按钮不能代替服务端权限校验。

## 通用内容状态

```text
draft → editing → checking → pending_review → reviewing
→ returned → resubmitted → approved → active → archived
```

个人草稿和 AI 临时结果可以不进入审核流程；正式大纲和教学日历必须经教学秘书审核后启用；课件和作业不强制教学秘书审核；试卷是否审核按试卷模块规则执行。

审核任务默认 SLA 为 3 个工作日，区分工作日和自然日，并允许提交人设置自定义截止日期。逾期阻止教学日历或正式内容启用，并向审核人、提交人和课程负责人发送提醒。教学秘书可直接处理，无需领取；允许多人协同评论，但最终处理人只能有一名。教学秘书无法处理时，课程负责人可转派审核任务；审核人不可审核自己提交的内容。

## 通用审核原则

- AI 只提供生成、检查和建议，不替代人工确认。
- 正式版本不允许直接覆盖，修改必须创建新版本。
- 退回必须有审核意见。
- 审核记录不能删除。
- 归档不等于删除，历史资料、版本、成绩和日志必须保留。
