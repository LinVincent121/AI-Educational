# 教学日历页面隔离规范

## 1. 目的

本规范用于保证所有“教学日历”页面的需求、代码、样式和数据修改只作用于教学日历，不影响顶部全局区域、左侧课程导航、课程切换、教学大纲和其他课程工作区页面。

本规范优先级高于教学日历的局部实现便利性。若某项改动无法满足本规范，必须先拆分方案或明确评审，不得直接修改公共代码。

## 2. 页面作用域

教学日历唯一页面作用域为：

- 路由：`#course/calendar`
- 页面根节点：必须存在唯一的教学日历根节点，例如 `[data-page="teaching-calendar"]` 或 `.teaching-calendar-page`
- 教学日历内部元素：统一使用 `tc-` 前缀命名，例如 `.tc-head`、`.tc-week-picker`、`.tc-content-list`

所有教学日历 DOM、事件、状态和样式都必须挂在该根节点下。没有教学日历根节点时，不得执行教学日历增强逻辑。

## 3. 明确禁止触碰的公共区域

下列区域属于平台公共壳层，教学日历需求不得改写、删除、移动或注入样式：

- 顶部全局导航、用户菜单、消息入口和全局设置入口；
- 左侧课程工作空间导航和课程切换控件；
- `index.html` 的页面骨架；
- `css/styles.css` 中的全局变量、全局布局和公共组件规则；
- `00-app-shell.js`、课程创建/处理脚本和教学大纲模块的既有渲染逻辑；
- `window.render`、`window.coursePage`、`window.shell` 等公共渲染入口；
- `.main`、`.layout`、`.side`、`.topbar`、`.app` 等公共布局选择器。

教学日历页面需要调整顶部或左侧导航时，必须作为独立的平台壳层需求处理，不得在教学日历任务中顺带修改。

## 4. 文件归属与修改边界

### 4.1 默认允许修改

- `prototype/js/modules/19-teaching-calendar.js`：当前教学日历页面的唯一首选实现文件；
- 教学日历专属资源文件（如未来拆分出的 `tc-*.css`、`tc-*.js`），但必须保持本规范的根节点和前缀约束；
- `course-v2-loader.js`：仅允许新增或更新教学日历专属模块的加载项和缓存版本，不得删除或重排其他业务模块；
- 本规范及教学日历 PRD 文档。

### 4.2 受保护文件

以下文件默认只读，不得因为教学日历需求删除、重写或“清理旧代码”：

- 教学大纲、课程工作区、课程切换、全局弹窗和公共基础模块；
- `css/styles.css` 的公共样式；
- 其他业务模块及其加载项。

若确实发现历史教学日历模块影响其他页面，必须先证明其调用关系，再做最小范围的隔离修复；禁止通过删除整个模块或从 loader 中移除模块来解决样式冲突。

## 5. CSS 隔离规则

1. 教学日历样式必须以教学日历根节点为第一层作用域，例如 `.teaching-calendar-page .tc-head`。
2. 新增类名统一使用 `tc-` 前缀，禁止使用无语义的通用类名覆盖公共样式。
3. 禁止在教学日历模块中直接定义或覆盖 `body`、`.main`、`.layout`、`.side`、`.app`、`h1`、`button` 等全局选择器。
4. 禁止通过 `document.head.appendChild(style)` 注入未加教学日历根节点限定的全局规则。
5. 禁止使用 `!important` 覆盖公共区域；必须使用教学日历根节点限定的更具体选择器解决冲突。
6. 响应式规则也必须限定在教学日历根节点内，不能改变全局页面的断点布局。

## 6. JavaScript 隔离规则

1. 教学日历脚本只在 `location.hash === '#course/calendar'` 且教学日历根节点存在时运行。
2. 事件监听优先绑定到教学日历根节点，禁止在 `document` 或 `window` 上监听后处理其他页面元素。
3. `MutationObserver`、`setInterval`、`setTimeout` 只能观察或更新教学日历根节点内部；离开页面时必须清理。
4. 禁止覆盖公共全局函数，包括但不限于 `window.render`、`window.coursePage`、`window.shell`、`window.openAI`、`window.closeAI`。
5. 教学日历需要调用公共能力时，只能调用稳定 API，不得重写公共实现。
6. 教学日历的状态、拖拽、弹窗和提交逻辑必须使用模块内函数或命名空间，不得向其他页面的 DOM 写入状态类。

## 7. 数据与本地存储隔离

- 教学日历只能读正式教学大纲和课程基础信息作为来源，不能反向修改大纲章节、课程切换状态或公共课程缓存。
- 教学日历本地存储 key 必须以 `ai-jiaowu-calendar-` 开头，并包含课程标识；禁止复用大纲或其他模块的 key。
- 教学日历的学时、周次和排课调整不得静默写回正式大纲来源数据。
- 切换课程时，教学日历只刷新自己的数据，不得清空或覆盖其他页面的草稿和筛选状态。

## 8. Loader 与缓存规则

1. `course-v2-loader.js` 的既有模块顺序视为运行时依赖，不得因教学日历改动删除其他模块。
2. 教学日历新增逻辑优先追加到教学日历专属模块，不得把代码塞入公共基础模块。
3. 修改教学日历后只递增缓存版本，不得通过删除其他脚本或改写公共入口来“解决缓存”。
4. 若必须拆分或替换旧教学日历模块，应先保留旧模块、完成页面回归，再在单独变更中清理，并记录影响范围。

## 9. 修改前后检查清单

### 修改前

- 确认需求只涉及 `#course/calendar`；
- 列出将修改的文件，默认不得超过教学日历模块、loader 缓存版本和规范文档；
- 检查顶部导航、左侧导航和课程切换当前状态，作为回归基线；
- 搜索待修改模块是否覆盖公共函数、公共选择器或其他路由。

### 修改后

- 教学日历页面功能和样式正常；
- 顶部导航、左侧课程导航、课程切换保持原样；
- 教学大纲页面的区块、版本切换、编辑器和预览保持原样；
- 课程总览、备课、课件、作业、学生画像和试卷页面可以正常进入；
- `node --check` 通过，`node tools/dev-check.mjs` 通过；
- 检查教学日历模块中不存在未限定作用域的全局 CSS、公共函数覆盖和跨页面 DOM 操作；
- 检查 loader 没有删除或重排非教学日历模块。

## 10. 变更验收原则

任何教学日历变更必须满足“页面内可见变化，页面外零变化”：

- 允许改变：教学日历内容、周次、排课、学时展示、教学日历专属弹窗和教学日历专属样式；
- 不允许改变：顶部、左侧导航、课程切换、公共主题、教学大纲页面和其他业务页面的布局与交互；
- 若验收发现页面外变化，先回滚该变更，再重新设计隔离边界，不得通过继续叠加覆盖样式修补。
